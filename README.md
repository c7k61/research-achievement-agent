# 科研成果核验 Agent

面向 AI Agent 应用开发求职的个人实践原型，通过材料检索、工具调用和原文引用，生成论文及专利的状态摘要。项目结合科研材料整理场景，适合演示 Agent 循环、RAG 的检索环节和结构化结果校验。

目前已实现 Python 命令行、SQLite 知识库、中文双字切分与 BM25 检索、四个工具、执行轨迹和 Ollama HTTP 适配。支持明确字段材料，以及两类常见中文通知模板。离线流程可直接运行。真实大模型尚待完成联调，协议测试使用模拟 HTTP 响应。

按顺序动手实现和验证，可阅读 [开发教程](docs/开发教程.md)。

## 三分钟运行

需要 Python 3.10 或以上版本。在本目录打开 PowerShell 执行以下命令。TXT 演示使用 Python 标准库。也可以直接运行 `python demo.py` 完成样例导入与问答。

```powershell
python -m research_agent ingest examples/materials
python -m research_agent ask "请核验论文和专利的当前状态，能写已发表和已授权吗"
python -m unittest discover -s tests -v
```

第二条命令输出两份虚构材料的核验结果和原文引用，并将执行记录保存到 `runs/latest.json`。输出中的 `offline-demo` 表示使用确定性演示规划器。

如需导入 PDF 或 DOCX，安装文档解析依赖。

```powershell
python -m pip install -r requirements.txt
python -m research_agent ingest private_materials
```

`ingest` 会用指定目录完整替换当前材料集。程序先解析全部文件，再在一个 SQLite 事务内写入，解析失败会保留上次成功导入的知识库。PDF 使用真实页码，DOCX 引用使用全文定位。扫描 PDF 需要先 OCR。

## 材料格式与核验范围

字段模式支持以下明确字段，字段必须逐字来自原件。模板模式还支持含明确录用结论的“稿件录用通知”和含受理结论的“专利申请受理通知书”，并引用原文措辞。其他排版可以导入和检索，无法可靠提取时会返回材料不足。每份材料对应一项成果。

```text
成果类型：论文
成果名称：示例论文题名
作者：作者甲，作者乙
期刊：示例期刊
证明类型：稿件录用通知
状态：已录用
```

支持的四组状态与证明类型如下。

| 成果类型 | 状态 | 证明类型 |
|---|---|---|
| 论文 | 已录用 | 稿件录用通知 |
| 论文 | 已发表 | 期刊正式发表记录 |
| 专利 | 已受理 | 专利申请受理通知书 |
| 专利 | 已授权 | 发明专利证书 |

专利材料使用 `发明人` 和 `申请号` 字段。重复且不一致的状态返回冲突，状态与证明类型不匹配、题名缺失或题名不唯一时返回材料不足。核验输出反映材料的明确记载，使用者负责核对原件真实性、作者顺序和实际贡献。

## 接入 Ollama

在本机运行 Ollama，并准备支持工具调用的模型。`--model` 应填本机实际安装的模型名称。

```powershell
python -m research_agent doctor --model qwen3
python -m research_agent ask "核验论文和专利状态" --mode ollama --model qwen3
```

默认地址为 `http://127.0.0.1:11434`。可以用 `--base-url`、`OLLAMA_BASE_URL` 或 `OLLAMA_MODEL` 配置服务。模型模式会把问题及被读取的材料发往你配置的模型服务，公开演示可使用仓库里的虚构样例。

适配依据 Ollama 官方的 [工具调用说明](https://docs.ollama.com/capabilities/tool-calling) 和 [Chat API](https://docs.ollama.com/api/chat)。应用循环提交 `messages`、`tools`、`stream=false`，将工具结果作为 `role=tool` 消息回传。

## 实现路径

```text
文档目录 → 解析文本 → 分页与重叠分块 → SQLite
问题 → 工具规划 → BM25 检索 → 读取原文 → 状态核验 → 已核验 ID 校验 → 引用摘要
                        每次工具调用 → JSON 执行记录
```

`store.py` 负责解析、事务导入和检索。中文按双字切分，BM25 在当前原型的小型材料集上按需计算，分块长度 650 字，重叠 130 字。

`agent.py` 提供四个白名单工具，分别为 `list_sources`、`search_evidence`、`read_source`、`inspect_achievement`。每次运行创建独立状态，读取后的材料才能核验，最终引用的 ID 必须在本次运行中核验成功。循环默认最多 14 轮、28 次工具调用。错误以工具结果回传，模型可修正参数。超时、无效响应和达到预算上限会明确报错。

模型最终只选择已核验成果的 ID，展示文本由程序根据核验字段生成。这样可直接检查出处，也便于对“录用到发表”“受理到授权”的状态错误做回归测试。JSON 轨迹记录工具输入、结果和耗时，可用于演示和排查，未收集模型内部推理。

## 当前验证与后续练习

`examples/demo-result.json` 保存一次可复现的离线运行结果。测试覆盖四种状态、否定和冲突记载、原文引用、重新导入、导入回滚、工具参数与读前核验限制、运行状态隔离、循环预算以及 HTTP 请求序列化和模拟响应往返。`examples/verification.txt` 保存交付时的测试输出。

这是小型材料集上的规则核验原型。通用通知书字段抽取、OCR、向量检索、模型效果评估和并发服务仍可继续实现。真实模型质量和延迟需要使用实际模型与单独的问答集测量，当前协议测试结果仅表示接口与控制流程通过。

可以使用 `python -m pip install -e '.[documents]'` 安装项目及文档解析依赖，随后直接使用 `research-agent` 命令。GitHub Actions 在 Python 3.10 和 3.12 上执行测试、离线演示和安装入口检查。
